# Хранение загруженных файлов

Всё, что загружают пользователи (аватарки, обложки проектов, версии, вложения чата), лежит в `MEDIA_ROOT`
(`backend/media` в dev, `/var/lib/paprika/media` в продакшне). Пути строит один модуль —
`backend/apps/core/storage.py`.

## Структура

```txt
media/
  users/
    <user_id>/
      avatar/
        <имя>-<token>.jpg
  <company_token>/
    .<название компании>                  # пустой файл-маркер
    <PROJECT>/
      <имя>-<token>.jpg                    # обложка проекта
      shots/
        <SHOT>/
          versions/
            <VERSION>-<token>/
              <VERSION>.mov
              <VERSION>.mov_converted.mp4
              <VERSION>.mov_thumb.jpg
          chat/
            <YYYY-MM-DD>/
              <имя>-<token>.<ext>
```

Пример вложения чата:
`media/k3m9x2qa/PRJ/shots/PRJ_0010/chat/2026-10-08/photo-7d2e91bc.jpg`

## Правила

1. **В путь попадает только неизменяемое**: токен компании, код проекта, имя шота, имя версии, id пользователя.
   Поэтому файлы никогда не переезжают. Переносить проекты между компаниями пока нельзя.
2. **Папка компании — случайный токен** (`Company.storage_token`, 8 символов `a–z0–9`). Он задаётся при создании
   компании и больше не меняется, так что название компании не видно в адресах файлов.
3. **Название компании на диске** — пустой скрытый файл `.<название>` в папке компании. Он нужен, чтобы человек без БД
   (например, при разборе бэкапа) понял, чья это папка. Маркер переименовывается вместе с компанией; если его не
   удалось записать, это только пишется в лог. Источник правды — БД.
4. **Токены у объектов**: у папки версии, вложения чата, аватарки и обложки есть свой случайный токен (8 символов
   `a–z0–9`, строчные — чтобы не было коллизий на файловых системах без учёта регистра). `/media/` отдаётся Caddy
   без авторизации, поэтому именно токен не даёт угадать адрес чужого файла. Токен компании секретом не является.
   Токен в аватарке и обложке заодно меняет адрес при замене, и браузер не показывает старую картинку из кеша.
   Имя загруженного файла у аватарки, обложки и вложения чата сохраняется, токен добавляется перед расширением
   (`Постер.PNG` → `Постер-k3m9x2qa.PNG`); расширение остаётся в том регистре, в каком его загрузили.
5. **Имена очищаются** перед попаданием в путь: остаются буквы (в том числе кириллица), цифры, `.`, `_`, `-`; всё
   остальное заменяется на `_`; ведущие точки убираются; длина ограничена. Разные имена могут дать одну папку
   (`A B` и `A_B`) — это допустимо: файлы внутри различаются токенами и ничего не перезапишут.
6. **Производные файлы** лежат рядом с исходником в папке версии, а их имя — это полное имя исходника с суффиксом
   (`PRJ_0010_v01.mov_converted.mp4`, `PRJ_0010_v01.mov_thumb.jpg`), чтобы было видно, из чего посчитано.
7. **Вложения чата** лежат в папке с датой загрузки по UTC. Точное исходное имя хранится в БД (`Attachment.filename`).
8. **Аватарка и обложка** сохраняют имя загруженного файла так же, как вложения чата: `<имя>-<token>.<ext>`.
9. **Удаление**: файлы удаляются по одному (сигналы `post_delete`, после коммита транзакции), затем убираются
   опустевшие папки. Папка не удаляется целиком, поэтому склеенные папки (правило 5) безопасны.
   Папка компании остаётся, пока в ней лежит маркер.
10. Поля файлов версий и вложений чата имеют `max_length=512`, аватарка и обложка — 255.

## Что осознанно не сделано

- Адреса файлов не защищены авторизацией: утёкшая ссылка открывает файл. Если понадобится, `/media/` можно отдавать
  через Django (проверка доступа) и Caddy; на диске при этом ничего не меняется.
- Перенос проекта в другую компанию и переименование шота/версии/кода проекта не поддерживаются, так как путь от них
  зависит.
- В Caddy для `/media/` добавлены заголовки `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex`.
  `nosniff` стоит для всего сайта; листинг папок выключен.
