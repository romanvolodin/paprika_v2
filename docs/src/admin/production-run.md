# Запуск Паприки

Это инструкция для администратора, который разворачивает Паприку на боевом сервере (VPS). Весь внешний трафик идёт через один контейнер **Caddy** — он же получает HTTPS-сертификат (автоматически, через Let's Encrypt), отдаёт собранный фронтенд и документацию, и проксирует запросы к бэкенду.

## Что нужно заранее

- VPS с установленными Docker и Docker Compose и утилитой `just`. Если сервер ещё не готов — см. [настройку VPS](vps-setup.md).
- Домен (например, `paprika.example.com`), A-запись которого уже указывает на IP-адрес сервера. Без рабочего DNS Caddy не сможет получить сертификат — и может даже словить временный бан от Let's Encrypt за повторные неудачные попытки, если DNS ещё не готов, а вы уже несколько раз перезапустили стек.
- Открытые на сервере порты **80** и **443**.

## Первый запуск

Клонируем репозиторий и переходим в папку проекта:

```bash
git clone https://github.com/romanvolodin/paprika_v2.git
cd paprika_v2
```

Дальше все команды выполняются в корне репозитория.

```bash
just init prod ваш-домен.example.com
```

`just init prod` задаст только один вопрос — email для уведомлений Let's Encrypt о продлении сертификата. Всё остальное сделает сама:

- сгенерирует случайные `PAPRIKA_SECRET_KEY` и пароль базы данных
- впишет домен в `backend/.env`
- создаст файл `.paprika-mode` (по нему остальные команды `just` понимают, что перед ними — продакшн, а не dev-машина).

После этого команда попросит:

1. убедиться, что домен уже реально указывает на этот сервер (DNS);
2. выполнить `just run`, а затем `just superuser`.

```bash
just run          # соберёт образы и поднимет весь стек в фоне
just superuser     # спросит email, пароль, имя и фамилию - создаст первого администратора
```

`just run` также автоматически накатывает миграции и собирает статику Django-админки при каждом старте `backend` — руками это делать не нужно.

Откройте `https://ваш-домен` в браузере. Сертификат Caddy получит сам при первом обращении — это может занять несколько секунд.
